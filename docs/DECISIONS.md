# DECISIONS — 决策记录

> 记录“为什么这么做”，避免以后反复推翻。每条包含：决定、理由、替代方案、后果。
> 状态：`accepted`（已定）、`provisional`（暂定，可改）、`deferred`（以后再说）。

---

## D001 只给自己用，Windows 优先

- 状态：accepted
- 决定：首版单用户、Windows；不做账号/云/商业化。
- 理由：最快落地；避免合规、分发、多端同步的复杂度。
- 替代：给朋友用/开源/商业化（暂不考虑）。
- 后果：安装包、隐私说明、内容分级可以后补；架构不为此过度设计。

## D002 Electron + React + TypeScript

- 状态：accepted
- 决定：Electron 桌面壳，React + TS 前端。
- 理由：生态成熟、Node API 直接可用、资料多、适合 vibe coding；Windows 通知/托盘/文件都成熟。
- 替代：Tauri（更轻但 Rust 门槛/生态小）；本地 Web（无托盘/通知/文件）。
- 后果：安装包大、内存高；可接受。

## D003 单伙伴，数据结构预留多角色

- 状态：accepted
- 决定：v1 只有一个 AI 伙伴；数据库/文件结构预留 `persona_id`。
- 理由：符合“一个 AI、多个房间”的立意；避免人格分裂。
- 替代：多角色共享/独立记忆（复杂，暂不做）。
- 后果：以后加角色不需要重做数据层，但 UI 仍以单角色为主。

## D004 纯文字 + 氛围背景，不做立绘/语音/桌宠

- 状态：accepted
- 决定：文本为主；暖色房间/夜灯/纸质背景，随时间变化；不做角色立绘、Live2D、3D、TTS/STT、桌宠。
- 理由：降低美术/授权/性能/工程复杂度；先把内容和记忆做好。
- 替代：2D 立绘/Live2D/VRM/语音（P3）。
- 后果：沉浸感靠文案、时间、背景、打字状态、UI 音效（默认关）来补；预留升级位。

## D005 人设等用户提供，不替用户写

- 状态：accepted
- 决定：只做 `persona.md` 模板、槽位、待设定占位、引导 UI；不写具体名字/性格/语气/示例对话。
- 理由：人设是用户的核心创作；AI 代写会跑偏。
- 替代：先做中性默认人格（暂不做）。
- 后果：P1 的聊天使用“待设定”中性提示；人设到位后接入。

## D006 记忆：Markdown 真相源 + SQLite 索引

- 状态：accepted
- 决定：`memory/**/*.md` 是真相源；SQLite 只做索引/结构化数据。
- 理由：用户可直接看/改/Obsidian；可迁移；不黑盒。
- 替代：SQLite 为主（用户看不到）；mem0/Letta（重、黑盒）。
- 后果：需要文件监听/索引同步/格式宽容解析；复杂度可接受。

## D007 记忆自动写入 + 收件箱

- 状态：accepted
- 决定：AI 自动提取记忆，进入收件箱；用户可审阅/修改/删除/合并。
- 理由：不打断聊天；又能纠正错误记忆。
- 替代：每条确认（太烦）；只手动（漏太多）。
- 后果：需要去重/敏感检测/置信度/来源；收件箱 UI。

## D008 记忆范围：咨询敏感，其他互通

- 状态：accepted
- 决定：心理咨询记忆默认敏感、不主动提、可加锁；其他房间记忆互通；不确定先问。
- 理由：兼顾“同一个 AI”和隐私。
- 替代：全部隔离（AI 失忆）；全部互通（可能冒犯）。
- 后果：需要敏感级别/检索惩罚/私密房间。

## D009 上下文分层 + 压缩 + 检索

- 状态：accepted
- 决定：每轮 8–12k 高信号内容；旧对话压缩归档；按需检索；不塞满 1M。
- 理由：Chroma 的 context rot 证明长上下文会降智；成本也会上升。
- 替代：全量 1M（短期简单，长期差）。
- 后果：需要摘要/检索/评测；回答可能“没找到记忆”，但不会假装记得。

## D010 模型：DeepSeek Flash，默认低思考

- 状态：accepted
- 决定：`deepseek-flash`；日常低思考/非思考；复杂任务 high；可手动切；后台批处理用便宜调用。
- 理由：1M 上下文、工具、视觉、搜索、便宜；低思考延迟低。
- 替代：全 high（慢/贵）；全非思考（复杂任务浅）；Pro（贵）。
- 后果：需要在 UI 提供思考档位；成本面板。

## D011 思考 + 工具：工具回合关思考

- 状态：accepted（实现细节可能调整）
- 决定：带 `tools` 的请求默认 `thinking: disabled`；纯聊天/咨询/规划可开 thinking；需要“深度思考 + 工具”时两阶段或自定义适配器。
- 理由：DeepSeek 要求带 tools 时回传 `reasoning_content`，否则 400；AI SDK 生态支持不完整。
- 替代：自定义适配器完整保存/回传 reasoning_content（更复杂，后续可做）。
- 后果：工具回合的“深度”略降；但稳定。

## D012 数据放工作区，私密内容不进 Git

- 状态：accepted
- 决定：`data/`、`memory/`、`config/`、`backups/` 在工作区；`.gitignore` 排除；API Key 加密。
- 理由：用户要求所有新建文件尽量在工作区；可见/好备份。
- 替代：AppData/Documents/云同步。
- 后果：工作区移动=数据移动；Git 仓库不含隐私。

## D013 API Key 用系统凭据加密

- 状态：accepted
- 决定：Electron `safeStorage`（Windows DPAPI）；渲染进程只见“已配置/后四位”。
- 理由：不把 Key 放明文/日志/Git。
- 替代：明文配置文件（不安全）；系统钥匙串库（额外依赖）。
- 后果：换 Windows 用户/重装可能需重填。

## D014 预算 ¥2/天，先充 ¥20

- 状态：accepted
- 决定：每日上限 ¥2；80% 提醒；超额降级；首次充 ¥20。
- 理由：正常使用约 ¥0.2–0.6/天；上限是保险丝。
- 替代：¥1/天（更紧）；不设上限（风险）。
- 后果：需要成本记录/降级逻辑/成本面板。

## D015 主动 2–3 次/天 + 免打扰

- 状态：accepted
- 决定：启动问候 + 每天 2–3 次轻量关心 + 任务/专注提醒；安静时段；自然语言免打扰；硬提醒仍响（可单独静音）。
- 理由：用户选择更有陪伴感；但必须有边界。
- 替代：每天 1 次（更克制）；只提醒（更冷）。
- 后果：需要频率控制/安静时段/DND 解析/通知分级。

## D016 提醒：托盘 + 开机自启 + Windows 通知

- 状态：accepted
- 决定：托盘常驻、开机自启、Windows toast；关闭窗口不退出（可设置）。
- 理由：关掉窗口也能提醒；日程可靠。
- 替代：仅运行时（会漏）；任务计划（复杂）。
- 后果：常驻后台；需要单实例/托盘菜单/通知权限。

## D017 导入格式：图片/Excel/CSV/Word/PDF/手动，不做 ICS

- 状态：accepted
- 决定：图片用 DeepSeek 视觉解析；其他解析文本；全部预览确认；不做 ICS。
- 理由：覆盖课表常见格式；视觉比本地 OCR 更适合中文截图。
- 替代：本地 Tesseract（中文差）；ICS（用户未选）。
- 后果：图片会发给 DeepSeek；需隐私提示；解析错误需可编辑。

## D018 18+ 一次性确认

- 状态：accepted
- 决定：首次启动一次性 18+ 确认；可在设置改；未成年切换全年龄。
- 理由：恋爱/亲密内容需要年龄边界。
- 替代：不设门槛（风险）；每次提醒（打扰）。
- 后果：首次多一步；内容策略可执行。

## D019 内容边界：恋爱/亲密可以，不直接描写性行为

- 状态：accepted
- 决定：允许恋爱/暧昧/拥抱/亲吻/更亲密暗示；不直接描写性行为；不涉及未成年/非自愿/亲属恋爱。
- 理由：用户选择；同时保留边界。
- 替代：全年龄（更保守）；不限（合规风险）。
- 后果：需要内容策略/拒绝话术/评测。

## D021 私密房间：默认明文 + 可选密码锁

- 状态：accepted（实现强度待定）
- 决定：默认明文（可编辑）；可选密码锁；首版优先访问锁，加密锁作为 P2；文档如实说明强度。
- 理由：用户要方便 + 可选隐私；加密锁工程量大。
- 替代：一直明文（简单）；一直加密（麻烦）。
- 后果：访问锁不防直接看文件；高敏感用户应选加密锁。

## D022 技能：编程/塔罗/游戏开发；不执行代码

- 状态：accepted
- 决定：学习路径 + 练习 + 项目 + 复盘；编程只给代码/讲解/审查；用户在外部运行。
- 理由：安全；首版不做沙箱。
- 替代：隔离运行（P2）；完整沙箱（太重）。
- 后果：AI 不能声称“我运行了/验证了”；需要明确提示。
