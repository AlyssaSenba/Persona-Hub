# MEMORY — 记忆系统设计

> 目标：让 AI 真的“记得你”，但不 creepy、不失控、不把错误记忆当成事实。
> 原则：**Markdown 是真相源，SQLite 只是索引；用户拥有最终解释权。**

## 1. 目标与非目标

### 目标

- 记住关系、称呼、边界、重要事件、偏好、习惯、近期状态。
- 记住“用户是怎么的人”（沟通风格、执行力、雷区），用于调整行为，而不是评判。
- 跨房间共享；咨询等敏感内容可控隔离。
- 用户可查看、搜索、编辑、删除、导出。
- 记忆可追溯来源与时间，可纠正。
- 长期使用不膨胀、不越聊越乱。

### 非目标

- 不记录每一句话（那是聊天记录，不是记忆）。
- 不做“读心术”；推断必须标置信度，可被用户纠正。
- 不把记忆当诊断/标签。
- 不偷偷保留用户删除的内容。

## 2. 分层

| 层 | 内容 | 衰减 | 默认检索 | 用户可改 |
|---|---|---|---|---|
| `core` | 关系、称呼、边界、纪念日、承诺 | 否 | 总是（小） | 是 |
| `episodic` | 按月/事件的故事摘要 | 可压缩 | 相关时 | 是 |
| `semantic` | 事实、偏好、习惯、雷区 | 可降权 | 相关时 | 是 |
| `sensitive` | 心理/健康/家庭/亲密 | 不衰减但隔离 | 仅授权/咨询房间 | 是 |

### 2.1 核心记忆（core）

- 例：称呼、关系类型、亲密边界、禁忌话题、重要纪念日、明确承诺。
- 不参与自动清理；AI 默认不删除；用户删除需确认。
- 每次对话都注入一个精简版（<500 tokens），不注入全部。

### 2.2 情节记忆（episodic）

- 例：“10 月第 3 周：用户在准备雅思，连续 3 天专注 50 分钟；周五情绪低落，聊了工作压力。”
- 按月/事件生成摘要；保留原文引用（可选）。
- 可压缩/折叠；不丢关键转折。

### 2.3 事实/偏好（semantic）

- 例：“用户喜欢晚上写代码”“用户不喜欢被叫‘宝贝’”“用户对花生过敏”。
- 新信息覆盖旧信息；旧信息标 `superseded_by`，不直接删除（可审计）。
- 低置信度推断放“待确认”，不当作事实使用。

### 2.4 敏感记忆（sensitive）

- 心理/健康/家庭/亲密/财务等。
- 默认不进入普通检索；不主动在聊天中提起。
- 咨询房间内、已解锁时可检索。
- 可加“私密房间”密码锁；锁定后不可搜索/引用/导出（除非解锁）。

## 3. 文件结构

```text
memory/
  core/
    relationship.md
    boundaries.md
    rituals.md          # 纪念日/固定仪式
  profile.md
  preferences.md
  people.md
  events/
    2026-10.md
  skills.md
  counseling/
    2026-10.md
  inbox/                # 可选：待审阅
```

### 3.1 条目格式

```markdown
- [2026-10-26] [core] 用户希望被称呼为“小六”。来源：首次设定。置信度：高。
- [2026-10-26] [semantic] 用户喜欢晚上写代码，上午容易分心。来源：对话 #c-123。置信度：中。
- [2026-10-26] [sensitive] 用户提到最近工作压力大，睡眠不好。来源：咨询 #s-9。置信度：中。不主动提。
```

约定：

- 一行一条，便于解析；长内容可多行，用缩进。
- `[日期] [层] 内容。来源：...。置信度：高/中/低。`
- 敏感条目加 `不主动提` 标记。
- 用户手动编辑不需要严格格式；索引器宽容解析，解析失败则整段作为一条 `semantic`。

## 4. 写入管线

```text
对话/事件
  → 候选提取（LLM，JSON）
  → 规则过滤（长度/重复/一次性）
  → 分类/敏感检测
  → 去重/合并
  → 置信度/来源
  → 写 Markdown + 索引
  → 收件箱（未确认）
```

### 4.1 触发时机

- 每 5–10 轮批处理（节省 token）。
- 会话结束/切换房间。
- 重要事件：任务完成、专注结束、咨询结束、用户明确“记住”。
- 用户说“记住 X”：立即。
- 用户说“忘掉 X”：确认后删除。

### 4.2 提取输出 schema

```json
{
  "memories": [
    {
      "layer": "core|episodic|semantic|sensitive",
      "kind": "relationship|preference|fact|habit|event|boundary|goal",
      "text": "一句完整、可独立理解的话",
      "tags": ["雅思", "学习"],
      "sensitivity": "normal|sensitive|private",
      "confidence": 0.0,
      "source": "user|ai|event",
      "sourceRef": "message-id"
    }
  ]
}
```

### 4.3 提取规则

- 只提取“对未来有用”的信息；不提取一次性寒暄。
- 用户明确说的 > AI 推断的；推断必须 `confidence < 0.8` 并进“待确认”。
- 不提取密码、身份证、银行卡、精确住址等敏感凭据；如用户主动提供，提示不要存/可删除。
- 不提取第三方隐私（朋友/家人的敏感信息）除非必要；优先抽象。
- 情绪状态可提取为“近期状态”，不作为长期人格标签。
- 关系边界/称呼变化必须提取为 `core`。

### 4.4 去重/合并

- 文本相似度（归一化 + 编辑距离/嵌入可选）> 0.9 → 合并。
- 同实体 + 同标签 + 时间近 → 合并/更新。
- 合并保留最新来源与时间；旧条目归档。
- 冲突：新事实覆盖旧事实，旧条目标 `superseded`。

## 5. 敏感检测

- 关键词表：心理疾病、自伤、自杀、性、家庭暴力、财务、住址、身份证、银行卡等。
- LLM 二次判断：上下文是否敏感、是否第三方隐私。
- 结果：`normal` / `sensitive` / `private`。
- `private` 默认不进检索；`sensitive` 仅在授权/咨询房间检索。
- 用户可手动改敏感级别。

## 6. 检索

### 6.1 查询构造

```text
query = 当前房间 + 最近用户消息 + 今日简报关键词 + 当前话题标签
```

### 6.2 信号

- FTS5 关键词匹配（中文分词可用简单 n-gram/外部分词；首版可用 `unicode61` + LIKE 兜底）。
- 标签/实体匹配。
- 时间衰减：`exp(-days/90)`。
- 重要性/置顶。
- 敏感惩罚：默认 -∞（不检索）；咨询房间内正常。
- 来源可信度：用户明说 > 事件 > AI 推断。

### 6.3 排序

```text
score = 0.55*text_relevance
      + 0.15*tag_match
      + 0.15*importance
      + 0.10*recency
      + 0.05*confidence
      - sensitivity_penalty
```

### 6.4 注入

- top-k 默认 6–10；总预算 1–3k tokens。
- 每条截断到 200–400 字；核心记忆单独精简注入。
- 注入格式：`[记忆 | 2026-10-20 | 高置信] ...`
- 回复引用时尽量带时间/来源；不伪造。

## 7. 跨房间事件

- 事件写入 `events`，再由摘要器生成“今日简报”。
- 事件类型：
  - `focus.started/completed/cancelled`
  - `task.created/completed/missed`
  - `review.completed`
  - `writing.submitted`
  - `counseling.started/ended`
  - `skill.practice`
  - `game.finished`
- 简报只包含“可公开给其他房间”的事件；咨询事件默认排除。
- 进入房间时注入简报；AI 可自然引用，不机械播报。

## 8. 矛盾/更新

| 情况 | 处理 |
|---|---|
| 用户改口（喜欢→不喜欢） | 新事实生效；旧条目标 `superseded_by`；不主动提旧 |
| AI 推断 vs 用户明说 | 用户优先；推断降为待确认 |
| 两条记忆冲突且都可信 | 保留两条，标“存在冲突”，下次相关时询问用户 |
| 用户纠正 | 立即更新；记录来源；可撤销 |
| 关系变化（分手/改变关系） | 更新 `core`；旧关系记忆归档；不反复提起 |

## 9. 压缩/衰减

- 每周：合并重复、压缩事件、清理低价值碎片。
- 每月：月摘要；季度/年度可选。
- 衰减：`semantic` 长期未用可降权，但不删除；`core` 不衰减。
- 清理前备份；可回滚。
- 不自动删除用户可能珍视的记忆；宁可归档。

## 10. 用户控制

- **查看**：记忆浏览器（列表/搜索/筛选/详情）。
- **编辑**：直接改文本/标签/敏感级别；保存后重建索引。
- **删除**：单条/批量/按主题；确认；删除索引；不偷偷保留。
- **忘记**：自然语言“忘掉 X” → AI 确认范围 → 删除。
- **导出**：Markdown/JSON/ZIP。
- **加锁**：私密房间密码；锁定后不可检索/引用。
- **审计**：最近修改记录（谁改的/什么时候/改了什么）。

## 11. “不会忘记”的语义

- 核心记忆不因时间/压缩自动消失。
- 换模型/换提示不丢记忆；记忆在文件里。
- 用户删除是唯一例外；删除需确认。
- 不保证“每句话都记得”；只保证“重要的事不被静默丢弃”。
- 如果检索不到，AI 应说“我没找到相关记忆”，而不是编。

## 12. 隐私与锁

- 咨询记忆默认 `sensitive`，不主动提。
- 可选“私密房间”密码锁：
  - 密码用 Argon2/scrypt 哈希存储；不存明文。
  - 解锁后本次会话可访问；超时/退出重新锁定。
  - 锁定状态下不参与检索、不显示在普通记忆浏览器、不导出（除非解锁）。
- 导出前提示包含敏感内容。
- 备份包含加密后的敏感文件；密码不备份。

## 13. 评测

### 13.1 提取评测

给定对话，期望记忆条目：

- 是否提取了核心事实？
- 是否漏掉边界/称呼？
- 是否把一次性闲聊误存？
- 敏感内容是否正确标记？

### 13.2 检索评测

给定 query，期望命中：

- 相关记忆在前 k？
- 敏感记忆是否被错误召回？
- 是否召回了过期/冲突记忆？

### 13.3 行为评测

- AI 是否引用了不存在的记忆？
- 是否在普通聊天主动提咨询内容？
- 用户删除后是否还“记得”？
- 记忆冲突时是否询问？

## 14. 反模式（明确避免）

- 把整段聊天记录当记忆塞进 prompt。
- 用向量库代替可读文件，用户完全看不到。
- 自动给用户贴人格标签（“你就是回避型”）。
- 把 AI 推断当事实。
- 删除后仍从备份/日志里“记得”。
- 为了“记得多”而保存隐私凭据。
- 在普通聊天主动提心理咨询内容。
- 记忆越存越多、从不整理。
